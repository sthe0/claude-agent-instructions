# Coordination and reasoning practices sub-index

Pointers to the leaves that govern how the root coordinator reasons, plans, delegates and verifies. The first group is also named inline in `CLAUDE.md`; the second group (reasoning and engineering practices) is read on demand and is not named there. This sub-index exists to keep `memory-global/MEMORY.md` under its byte ceiling and the always-loaded surface small; the root index holds one pointer here. Membership: a leaf belongs here if it states a coordination or reasoning practice rather than a tool or machine fact.

- [Coordinator objective](../coordinator-objective.md) — what to minimize (cost / tokens / user time and attention / clicks / resolution time) and maximize (autonomy / reliability / controllability / verifiability); how to resolve trade-offs between conflicting axes.
- [Reasoning and task solving](../reasoning-and-task-solving.md) — understand before acting, plan and approval, when stuck, memory vs prompts, self-check before first production edit.
- [Workflow debug investigation](../workflow-debug-investigation.md) — ordered checklist for orchestrated pipeline failures: reference baseline, topology/causality, code delta, then infra logs; hypothesis portfolio.
- [Partition markers (M1–M4)](../partition-markers.md) — delivery partition: into how many independently-shippable PRs/tickets the approved plan is cut; applied after plan approval, before implementation. Distinct from the planner's step-level decomposition.
- [Acting without asking](../acting-without-asking.md) — side-effect-free actions and plan-scope-declared changes are pre-authorized; 1-lookup budget for unknown tools; substantive plan changes of a user-approved order are self-approved inside its boundary, the user's outside it.
- [MCP-first dispatch](../skill-first-dispatch.md) — MCP tool > skill > raw CLI before hand-rolling Bash for known domain ops; scan the system-reminder skill list; class-of-operation → skill-family table; `fewer-permission-prompts` as the audit habit.
- [Delegatable work patterns](../delegatable-work-patterns.md) — two shapes the opus main thread must hand to a cheap-model sub-agent (A post-spawn monitoring, B initial codebase/data exploration); model-tier heuristic (haiku retrieval / sonnet search / opus reasoning); the `Agent` tool inherits opus unless `model:` is set.
- [Long-job monitoring](../long-job-monitoring.md) — drive a long external job (hours/days) to terminal state yourself: detached OS poller (zero model tokens) + self-scheduled `ScheduleWakeup`/`CronCreate` wakeups report transitions; cheap `Agent` only at the DoD milestone. Anti-pattern: offloading the cadence to the user ("ping me when it's done").
- [Memory hierarchy](../memory-hierarchy.md) — when to spin off `<subdir>/MEMORY.md` sub-indexes (monotonic / domain-coherent / display pressure); mechanics, anti-patterns, retire procedure.
- [Memory usage](../memory-usage.md) — when to read / verify / write memory and what never to persist (reconcile mutable-state leaves against live source; cite OS/version claims; behavioral rules go to CLAUDE.md not memory); the hygiene rules behind the three-scope table.
- [Leaf schema (`leaf/v1`)](../leaf-schema.md) — rigid section shape for ordinary reference/feedback/system-knowledge leaves (`## Difficulty` / `## Guidance` / `## See also`); `verify-leaf-structure.py` enforces opted-in leaves, grandfathers the rest; experience leaves use `difficulty/v1` instead.
- [Memory temporal frontmatter](../memory-temporal-frontmatter.md) — two-field contract: `created`+`last_verified` required and tool-stamped (all 3 scopes, all schemas); `last_accessed` is retired — validators reject re-introduction.
- [Plan activity ontology](../plan-activity-ontology.md) — the 8 elements a plan must cover (order; material+result; control criterion; means [immutable]; method; conditions+invariants; actor+capability; refutable principle) mapped to `agentctl/plan.py` fields; substantive-only; recursive sub-ordering (any unmet element → service sub-plan) as the genesis of composite plans.
- [Token-economy plan](../token-economy-plan.md) — living programme of context-engineering / cache-aware / static-prefix changes; self-improvement reads this before proposing new token-economy edits and updates rows in place.
- [Spawning specialists](../spawning-specialists.md) — full `claude -p` spawn mechanics: spawn-template inputs, budget tiers, recursion cap, monitoring a running spawn, after-spawn `status`+`log` checks, `bypassPermissions` discipline, return markers, no-continuation-channel (never background-and-wait-for-notify).
- [Handling escalations](../handling-escalations.md) — how the manager resolves each specialist return marker (PLAN-READY / CLARIFY / REPLAN / PERMISSION-REQUEST / ESCALATE / INCOMPLETE / COMPLETED) and the continuation-prompt templates for re-spawning.
- [Landing discipline](../landing-discipline.md) — at the resolution gate committed work must reach trunk/main, not sit on a personal branch; checkpoint-vs-delivered, land mechanisms (git ff / PR), and the rule to land before the resolution AskUserQuestion (land → verify-final → marked ask).
- [Capability before offload](../capability-before-offload.md) — when you hold the tools and rights, do the step yourself; verify a claimed "no CLI path" with a memory check and a `--help` check before sending the user to a UI.
- [Doubt your own snapshot](../doubt-own-snapshot.md) — when a user's requirement seems to contradict what you observe, refresh your own (possibly stale) source before doubting the requirement or asking a false-premise question.
- [Hedge phrase is not a question](../hedge-phrase-not-a-question.md) — "вы решите"/"просто скажите" reads as closure but leaves nothing to click; pose the real choice as `AskUserQuestion` instead; prose-only backstop until a structural detector for silent decision points exists.

- [Functional-place difficulty](../function-place-difficulty.md) — a difficulty is a symptom on the морфология layer; its cause is a broken functional place in the организованность (функция layer, not 1:1) — problematize before optimizing the literal order.
- [Effort-divergence trigger](../effort-divergence-trigger.md) — the engine enters the difficulty cycle by itself when actual effort runs past the CURRENT plan's re-derived estimate by the configured multiple: four scales, a window opening at plan approval, a terminal that diagnoses rather than asking, and the honest weakness that the estimate is set by the same actor it constrains.
- [Outcome format](../outcome-format.md) — the five-point shape of an actionable report: status / what-was-done-by-step / artifacts-with-clickable-markdown-links / next-steps-only-if-not-done / main-first presentation with interval estimates.
- [Spine fallback](../spine-fallback.md) — the five-step hand-walk of the substantive-task spine when the agentctl engine is not started or unavailable.
- [Formalization ladder L1-L3](../formalization-ladder-l1-l3.md) — for a reasoning/research deliverable: the L1 (claim ledger) / L2 (recompute) / L3 (full formalization) ladder with a criterion per rung and an explicit L3-refusal rule for empirical claims; why regex enumeration was rejected; the honest enumeration residual (recall<100%, DECOY, junk-dismiss) the ledger cannot close.
- [Question-provenance gate](../question-provenance-gate.md) — the `premise` plugin gates plan_approval on question provenance (every planning question dispositioned; the enumeration cross-check is retired, customer questions come from review acts) — the plan-approval-axis twin of the ledger's resolution-axis claim gate; auto-arms on SUBSTANTIVE alone; also gates the plan against the ORDER (every order element covered by a stage or cut with a reason, the cut list + plan size visible in the essence the user approves); carries the honest ceiling (the F3b runner-health escape is retired with the enumerator), the designed-in `plan.goal`-parking incentive gradient (F7), and the deliberately unenumerated order.
- [Behavioral conformance control](../behavioral-conformance-control.md) — conformance (actual behavior vs. instructions/plan) is a verification axis checked at every step boundary and at resolution, not only when the user notices; every expected action (incl. an action's implicit precondition) is a conformance object; two-layer coverage (prose perception net + the mechanized obligations-ledger slice) with an extension recipe for mechanizing a newly-found case.
- [Plan-presentation delivery gate](../ask-user-question-split-turn.md) — the essence rendering must land as a completed turn's final message bound to `plan_sha256` before `cmd_approve`; `hook-plan-delivery-gate.py` enforcement, the two-prover split, the fail-open classifier scoping the gate to the approval ask, and three residuals. The former universal AskUserQuestion turn-split (deliver-as-final-message, sleep-2 timer) is retired — the client render bug it worked around is fixed on 2.1.216.
- [Recording experience](../recording-experience.md) — the execution-time how-to that follows the CLAUDE.md resolution gate: quality bar (decide whether to record), search-before (extend|new), `difficulty/v1` schema, ticket-thin leaf, required `resolution_confirmed_by_user` frontmatter, self-critique → self-improvement auto-trigger.
- [Regex not for semantic classification](../regex-not-for-semantic-classification.md) — any lexical matcher (regex, keyword list, token overlap, similarity ratio) deciding free-text MEANING (hard block, classification, dedup/clustering join) determinizes perception at the wrong level; demote it to a candidate generator and let a fail-open model judge decide, mirroring `agentctl/advisor.py::judge_binary_ask`; the structural-vs-semantic boundary + hook-suite audit.
- [Verify the right axis, report honestly](../verify-right-axis-report-honestly.md) — static checks (imports/tests/build-diff) never substitute for runtime correctness, durable-store coverage, universal-quantification, or provenance/conformance axes; each is its own axis checked on its own terms.
- [Own research precedes escalation](../own-research-precedes-escalation.md) — spend the cheap channels already held (memory, repo, docs/web, MCP, a domain-expert subagent) before a question reaches the user, at every moment a question arises, not only at plan approval; scope by kind (knowledge vs decision/permission/preference).
- [Effect, not executor, classifies Substantive](../effect-not-executor-classifies-substantive.md) — a task is Substantive whenever its effect is external/irreversible, even when the agent only delivers commands/config for the user to run rather than executing them itself.
- [Unanswered question survives the turn](../unanswered-question-survives-turn.md) — a user reply's embedded question, or an AskUserQuestion that timed out after answer content was already written mid-turn, must be restated and re-asked at the next gate rather than silently dropped.

## Reasoning and engineering practices

- [Published-artifact complaint is a dual signal](../artifact-complaint-dual-signal.md) — a readability/formality complaint about a published artifact means both fix-it and diagnose-why-the-gate-missed-it, same turn.
- [Recurring normalize-factor is an architecture signal](../recurring-normalize-factor-is-architecture-signal.md) — ≥2 normalize cycles naming factors in the same underlying category means the prior re-norming was cosmetic; the replanning task must surface a structural alternative to the user, not another patch.
- [Abandonment is a last resort for a working mechanization](../abandonment-is-last-resort-for-mechanization.md) — when critique traces a mechanization's failure to its own operating cost (false positives, friction) rather than to a wrong premise, evaluate a narrowed version before full reversion, and name reversion's autonomy cost explicitly rather than presenting it as the safe/pragmatic pick.
- [Typical coordinator pitfalls](../coordinator-pitfalls.md) — anti-patterns to avoid as the root coordinator; signals that point to specific corrective actions.
- [`resolve --by user` needs a real ask](../resolve-by-user-needs-real-ask.md) — never call `agentctl resolve`/`accept --by user` without a genuine, same-turn `AskUserQuestion` — even for a trivial, already-verified small change; self-caught 2026-09-15.
- [Verify artifacts before presenting](../verify-artifacts-before-presenting-to-user.md) — personally re-check concrete claims against live bytes BEFORE presenting a plan/report, not after being asked; trusting subagent review + digest-match is not the same as your own confirming pass. User-flagged as an engine-mechanization target (shared verification helper, called from present-plan/approve/stage-review), not just prose.
- [Backlog triage as a task type](../backlog-triage-practice.md) — "разбор беклога" across Core (GitHub Issues) + the Org tier's tracker: compact priority rubric (breadth × recurrence-mass / cost-to-resolve, hard partial order on explicit deps only) + re-run-per-visit procedure; references, doesn't duplicate, the general coordination-spine docs.
- [Improvement scan](../improvement-scan.md) — standing, mechanized backlog + telemetry producers behind the `improvement-scan` skill; two resume schemes (board-diff vs ledger-cursor) and the report-only boundary.
- [Log-reading discipline](../log-reading-discipline.md) — 10-line cap per tool call when reading logs; aggregate first, surface digests.
- [Code comment discipline](../code-comment-discipline.md) — default no comments; comment only when the *why* is non-obvious; build / config files (`ya.make`, `Dockerfile`, …) are not exceptions; concrete antipatterns from a past PR review.
- [Mirror the working caller before inventing a bypass](../mirror-working-caller-before-bypass.md) — on missing ambient context inside a constrained env (job/sandbox/frozen layer), replicate how the existing working caller establishes that context before reaching for an env/quota/path shim.
- [Tests accompany code](../tests-accompany-code.md) — any code change ships with tests verifying it; symmetric default for developer (writes) and reviewer (rejects a diff lacking them); named non-testable escape class; soft commit-msg backstop.
- [Universal-negative control via mutation catalogue](../universal-negative-control-via-mutation-catalogue.md) — a claim like "no narrowing/widening passes" is discharged by a committed, in-suite mutation catalogue over the subject (assert a named control goes RED per mutation), not by enumerating more input axes from recall — the existential twin of the planner's universally-quantified-done-criterion rule.
- [Docs accompany an architectural change](../docs-accompany-architectural-change.md) — an ADR / new subsystem / changed coordination model is not delivered until the canonical read-first surface (README + docs index) reflects it; symmetric to tests-accompany-code on the documentation axis; named escape class; resolution gate checks the doc axis, not just tests-green.
- [Review accompanies code](../review-accompanies-code.md) — for review-gated work a code-producing stage is not done until its change is an OPEN, self-justified review request (open ≠ merge — a deferred trunk-land never licenses a deferred review); clone an exemplar config by field-level semantics against the target's requirements, not surface, and put non-obvious-field rationale in the commit/PR description where inline comments are impossible (JSON); symmetric author(developer)/reviewer; twin of tests-accompany-code on the review axis.
- [Committed files earn their place](../committed-files-earn-their-place.md) — the keep-criterion for a helper/script is usefulness to OTHER developers (not an in-repo caller): useful-to-others → commit into the product tree + document why/when/how; useful-only-to-us-later → personal `junk/`; one-shot self-check → uncommitted evidence dir. Symmetric developer(author)/reviewer(should-fix) rule.
- [Code links carry a revision](../code-links-carry-revision.md) — a cited code link that is line-anchored (`#L…`) must be revision-pinned (an internal VCS's `?rev=`, GitHub commit-SHA permalink) or it rots as lines drift; file/dir links are drift-proof and exempt. Symmetric developer(author)/reviewer(should-fix); pairs with the tech-writer code-reference formatting-tier rule.
- [Systemic pattern scan](../systemic-pattern-scan.md) — at resolution: scan experience for recurring friction; run overcome-difficulty against the agent-system-as-plan; route the resulting architectural proposal through self-improvement.
- [Specialization & skill usage tracking](../specialization-skill-usage-tracking.md) — at resolution, generate `name | count | purpose` table for every specialization spawn and `Skill` / `Agent` invocation via `scripts/tool-usage-report.py`; feeds the experience leaf's "Cost, effort, and tool usage" section.
- [Skill catalog curation](../skill-catalog-curation.md) — discipline for keeping the user-invocable skill catalog lean; periodic audit via `scripts/skill-usage-audit.py`.
- [Large tool-output discipline](../large-tool-output-discipline.md) — pipe high-volume Bash commands through `scripts/offload-large.sh` so the model gets a head+tail digest and the full bytes live in `/tmp/cc-scratch/`.
- [Plan-file split (Superseded)](../plan-file-split.md) — legacy manual split; large plans now use hash-pinned references per `docs/adr/0012-hypertext-plans.md` (`plan-externalize`, `plan-convert`).
- [Verify ownership before deleting shared state](../verify-ownership-before-shared-state-delete.md) — "no live process foothold" ≠ "no owner": a suspended/resumable session owns its worktree/mount/branch/scope-file across idle gaps; check the durable session record (scope registry / transcripts) not just `/proc`, and bias the classifier fail-safe (KEEP when ownership can't be proven absent).
- [Re-dispatch continuity check](../redispatch-continuity-check.md) — dispatch forks a FRESH worktree for an independent stage every time (`_continuation_worktree` is gated on `depends_on`), so re-dispatch silently re-derives finished work; check existing `.claude/worktrees/*` and run the verify_command there first. Also: `resolve-permission --decision granted --scope stage|once` now materializes a runtime `[stage.grants]` entry (confirm via `stage-grants`), and Bash allow-patterns match the literal command string, not a resolved path. Re-attest after a substantive replan is OPT-IN: `dispatch --re-attest` (plain `dispatch` respawns).
- [Plan cost_tier underestimates an empirical-measurement stage](../plan-cost-tier-empirical-stage-underestimate.md) — tier a multi-variant measurement or acceptance-judge-gated stage `"large"`, not `"medium"`, at plan-authoring time — the concrete authoring fix for the effort-divergence trigger's "estimate set by the same actor it constrains" blind spot.
- [`guard_exempt_paths` has no grant coupling](../guard-exempt-paths-no-grant-coupling.md) — the field lifts the repo-root write-guard deny on a declared path with no code-level check that the path is covered by an actual validated stage grant; open follow-up, flagged independently by a code-reviewer and a plan-review thinker pass on the same diff.
- [Plan control-criterion hygiene](../plan-control-criterion-hygiene.md) — four control-criterion authoring norms: declared venue, no unverified current-behaviour fact, bounded counts, no self-rewrite.
- [Narrowed-contract callers are material](../narrowed-contract-callers-are-material.md) — a stage that adds a required argument or a refusal lists every grep-found caller and the pin suites as material, and every hook-required generator as a grant.
- [A plan's cost estimate for a remedy can conflate two different operations](../compose-query-cheaper-than-full-reissue.md) — verify the actual cost mechanism in code (e.g. a cheap read-only state query vs. an expensive full re-walk/re-spawn) before accepting the plan's own stated cost assumption; concrete instance in `agentctl`'s `--review-topo` driver's `compose()`.
- [Investigate a cited precedent](../investigate-cited-precedent.md) — when the user points at a specific prior success (ticket / run / commit / PR), read HOW that precedent actually did it before theorizing from the current snapshot; positive-exemplar twin of doubt-own-snapshot, concrete form of the reference-baseline pass; also covers a precedent suggested by a third party inside a tracked thread, not only one the user relays live.
- [Mini-OD on a self-devised-workaround blocker](../mini-od-self-devised-workaround.md) — declare-before-retry binds before a second alternative approach to any blocker inside a self-built workaround, not only a failed orchestrated job; the Mismatch sentence doubles as the escalation question.
- [Determinize required specialist dispatch](../determinize-required-specialist-dispatch.md) — the `review_dispatch` plugin proactively names two engine-required, non-stage-actor specialist spawns (thinker @ plan-review on `submit_plan`, code-reviewer @ a `spawn:developer` stage on `dispatch`) in front of each obligation's pre-existing reactive gate; the `_SLOT_SPECIALIST` table as the extension seam; why `dispatch` not `replan` is the safe observer event.
- [Robot-run ACL access](../robot-run-acl-access.md) — when data-warehouse/orchestration-platform ops run under a robot identity, set a team idm-group read ACL on EVERY op (named constant, all ops not a subset) or humans can't read stderr/logs/artifacts; verify a human token actually reads a finished op.
- [Instruction-development queues](../instruction-dev-queues.md) — the 3-tier tracking model (Core / Org / Project): each tier has an internal backlog + a report inbox; collapse rule when filers==editors (Project→one queue); stream-separation by queue (Org: ORG-BACKLOG backlog / ORG-REPORT reports) or by label (Core GitHub Issues: `difficulty` reports / `backlog`); per-project queue via the `agent-project.json` `instruction_queue` field. **Core venue is PUBLIC** — split mixed Core+Org items by tier at filing time; pre-publish `scripts/check-org-neutral.py` on every Core-issue body.
- [Review-object requirements contract (seed)](../review-object-requirements-contract.md) — starter, explicitly-refinable checklist of properties ANY reviewed object must satisfy regardless of type (internal consistency, verifiable-origin claims, reachable controls, explicit scope); a `leaf/v1` seed, not yet an induced principle.
- [Verify-command scope and frozen revision](../verify-command-scope-and-frozen-revision.md) — a stage's `verify_command` must scope tolerance/strictness to only the ids/fields it itself changed (never every id in the section), and read a historical self-claim via a frozen revision, never a live `open()`; the final-landing stage, not the additive stage, carries the tolerance for a later authorized extension.
