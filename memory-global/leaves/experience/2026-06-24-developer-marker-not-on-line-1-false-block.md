# Spawned developer's return marker after a prose preamble false-BLOCKs the engine

## Difficulty
The spawn-wrapper return-marker contract requires the marker (COMPLETED: / PLAN-READY: / INCOMPLETE: / …) on the FIRST non-empty line of the specialist's final message. A developer subagent's natural output shape is a short result summary FIRST, then the marker — so the wrapper prefixes MALFORMED: and `agentctl dispatch` records the stage as BLOCKED. The work itself passed; the block is a pure false-negative on output FORMATTING. It recurred TWICE in one task (stage 1 verifier + stage 2 migration), each time forcing the manager into a manual recovery loop: independently re-verify the deliverable, `agentctl unblock`, then `record-result --status passed`. The divergence is plan-vs-reality at the dispatch step: expected marker→PASS, actual MALFORMED→BLOCKED, with no defect in the underlying result image.

## Order & criterion
Expected at dispatch: a successful stage returns its marker and the engine records PASSED. Acceptance criterion: the stage's deliverable meets its done_criterion AND the engine advances without a manual unblock.

**Acceptance check:** A spawned developer stage that meets its done_criterion advances the engine to the next stage with no manual unblock/record-result recovery by the manager.

### 2026-07-24 — closed at the source by a dedicated second-pass extractor
- Where it arose: the self-improvement fix for this whole leaf's class, run as a 3-stage agentctl substantive task (branch `marker-second-pass`, landed commit `efd3f45` — the conformed amend over the original delivery `537bc12`/`8ef85ad`; see the 2026-07-24 (cont.) block for the defensive cycle between them).
- What landed: `scripts/lib/marker_extract.py` — an UNCONDITIONAL second pass (the model is the PRIMARY classifier after every spawn, not a rescue run only when a regex scan already failed). It reads the specialist's final output and returns exactly one marker from the closed `RETURN_MARKERS` set (the escape wrapper uses its own 3-marker vocabulary). The deterministic rule (`check_planner_return`/`canonicalize` in `scripts/lib/planner_plan_check.py`, `parse_marker` in `scripts/agentctl/dispatch.py`) then validates token-in-set and canonicalizes once. Wired into all three spawn wrappers via one named `_build_extraction`/`extraction_active()` guard.
- Why the two earlier attempts were rejected: (a) emphasis-tolerance (strip a leading `**…**`/`` `…` `` in the regex, landed briefly at 1560e3e) only patched the ONE 2026-07-23 surface and left the prose-anchor — the shared root cause — intact, so the next unforeseen markup would re-open the class; (b) a reserved sentinel frame (force the specialist to emit the marker inside a machine-only delimiter) pushes the burden onto every specialist's output discipline, which is exactly the brittle contract that kept failing. The user rejected "search for the marker word in free text" as an unreliable crutch and chose the second-pass extractor.
- Perception/rule split: identifying WHICH marker the specialist meant is perception (a cognitive judgement) and now belongs to the model; validating the named token against the closed set, canonicalizing, and routing stays a deterministic rule. This is the CLAUDE.md rule-vs-perception principle applied to the exact place it had been violated.
- Fail-closed polarity (and why it differs from advisor.py): an unparseable / out-of-vocabulary / errored model reply maps to NONE → MALFORMED, NEVER a guessed marker — because a wrong marker misroutes the engine silently, so the safe default is to refuse and fall back to manual re-verify. This is the OPPOSITE of `agentctl/advisor.py`'s judges, which fail-OPEN (a missing/degraded judgement must not block a legitimate action); the polarity is chosen per consequence-of-being-wrong, not by convention.
- Kill switch: `AGENTCTL_MARKER_EXTRACTOR=0` makes the guard False → extraction None → byte-identical legacy any-line path, so the pass is fully reversible; `claude` off PATH degrades gracefully to that same legacy path.

### 2026-07-24 (cont.) — a defensive review cycle caught a fail-OPEN in the delivered extractor before it landed
- Where it arose: verifying the delivered second-pass extractor (branch `marker-second-pass`) before landing. The original delivery (`537bc12`, later the pre-fix HEAD `8ef85ad`) passed its own tests but an independent code-review found a silent security regression; the plan's defensive cycle (difficulty → replan → re-execute stage 2 as a single AMEND) closed it, landing as `efd3f45`.
- The fail-OPEN (the load-bearing catch): the canonical envelope's FIRST line is read by `agentctl.cli.cmd_dispatch` as the router body, and for a PERMISSION-REQUEST that body is fed to `permissions.check_permission`, a case-insensitive SUBSTRING match against the user's granted patterns. The delivered `canonicalize` put the MODEL-authored digest on the marker line (`<MARKER>: <digest>`), so untrusted model text containing a granted substring (e.g. `git push`) would have auto-skipped the user's permission ask — a fail-OPEN regression against the legacy always-ask polarity. Fix: the marker line is now BARE (`<MARKER>:`), the digest moves to its own `Digest:` line (off the routed line), so the router body is `""` and the permission path defaults to always-ask. `plan_path` (also model-authored) gets the same newline-sanitization so an injected newline cannot forge an extra envelope line.
- Second refinement (FIX 2): `parse_marker` collapsed to ONE ordered scan — `MARKER_RE` and the `MALFORMED:` test share a single loop body per line, first-in-document-order wins. Two sequential passes (all lines for a marker, then all for MALFORMED) would let a stray `COMPLETED:` inside a MALFORMED envelope's preserved original out-rank the envelope — itself a fail-OPEN mis-route. Both fixes are mutation-proved: restoring `f"{marker}: {body}"` → 18 RED; splitting the scan → the MALFORMED-outranking control goes RED with `+ COMPLETED`.
- Live proof the fix matters, observed during its own review: the independent code-reviewer's genuine verdict `REVIEW: pass` was itself stamped MALFORMED by the still-live LEGACY backtick parser (it wrote the marker in backticks) — the exact class of false-block this task removes, reproduced on the reviewer of the fix, because the fix was not yet landed. The coordinator read the actual output to confirm the pass. A cleaner demonstration of the difficulty is hard to construct.
- Process frictions worth carrying (candidates for their own norming): (a) the replan-coverage gate (`replan_coverage_blockers`) checks each critique `invariants_to_preserve` as a normalized substring of the stages' conditions+invariants — running that check BEFORE spawning the plan-review avoids an extra re-review round when the plan doesn't yet literally contain the preserve-ledger; (b) `agentctl dispatch` has no constraint-injection flag, so a review clarification that lands AFTER plan-freeze cannot be pushed to the developer through the sanctioned path — the frozen plan's STEP text must already carry it (it did: "exactly as STEP 2 now specifies"); (c) `spawn-specialist.py --context-dossier` treats its argument as a FILE PATH first, so inline text raises "File name too long" — pass the brief via `--plan` with `**<<this step>>**` instead.
- Delivery-hygiene tension resolved by the user: the sole failing pre-commit check `verify-memory-index` fails ONLY on 3 untracked protected experience leaves from a parallel session (out of scope, must not touch), so a hook-passing commit was impossible without touching them; the user chose to accept the `--amend` made with `git commit --no-verify` (Q2 waived for this justified, orthogonal-to-the-change case) rather than relocate another session's residue. The commit content passes the other 16/17 checks.

## Common core & variations
**Common:** Spawn returns a terminal line the wrapper does not accept as a marker (MALFORMED) and agentctl would route to BLOCKED/ESCALATE, but the underlying work fully or partially succeeded; manager must independently re-verify the artifact (the VCS status/log/diff/PR view, re-run tests) rather than trust the marker, then finish only the residual steps.

**Variations (historical catalog):** the rejected-marker cause differed — 2026-06-24 = prose preamble before the marker (formatting); 2026-06-25 = budget exhaustion / mid-flight error so no marker emitted at all; 2026-07-11 = marker correctly formatted and well-placed but its *token* absent from the known `RETURN_MARKERS` set (compounded by the set being duplicated across copies with a drift-guard covering only some); 2026-07-23 = token present, correctly named, on the right line, but wrapped in **markdown emphasis/code-span** (`**COMPLETED:**` / backticked). All four share ONE root cause: a meaningful English word ("COMPLETED", …) pressed into service as a machine anchor and read out of the specialist's free prose — every surface variation (position, markup, token-set drift) is a symptom of anchoring on prose.

**Standing resolution (2026-07-24):** all four are closed at the SOURCE by the dedicated second extraction pass described in the 2026-07-24 context block — a bounded, closed-set, role-HINTED (never role-restricted), fail-closed model call names the marker; the deterministic rule then validates token-in-set, canonicalizes once, and routes. Because identification no longer anchors on prose, position / markup / emphasis no longer matter. The residual failure mode is an extractor that returns NONE, which fails CLOSED to MALFORMED and is recovered exactly as before (verify the artifact → `unblock` + `record-result`), with `AGENTCTL_MARKER_EXTRACTOR=0` as the escape hatch to the legacy path. Topology of the fix: one shared home (`scripts/lib/planner_plan_check.py`, imported by both spawn wrappers), one new perception module (`scripts/lib/marker_extract.py`), one router (`scripts/agentctl/dispatch.py`), and one distinct-vocabulary escape wrapper (`scripts/spawn-cursor-escape.py`) — NOT four duplicated copies patched in lockstep. The budget-calibration note from 2026-06-25 (use `--budget medium` minimum for a developer spawn) still stands independently.
