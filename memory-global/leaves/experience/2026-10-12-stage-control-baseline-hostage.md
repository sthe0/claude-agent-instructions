# A stage control asserts an absolute property of a suite or tree the delivery does not own

## Difficulty
A stage verifies its own change by asserting that a whole suite, a whole registry or a whole working tree is clean. The shared resource already carries a change-independent red, or acquires one from an unrelated commit or an untracked parallel edit between authoring and run, so the control fails for a reason outside the delivery. The honest repair is a base-relative assertion, but the first reaction is to weaken the control or to attribute the red to the delivery.

**Functional ground:** A control reads state the delivery shares with others (the test suite, the registry, the working tree) and asserts it absolutely, so the delivery is held hostage to failures it neither caused nor can fix.

### 2026-07-22 — Backlog candidate (TRIGGERED): differential verify for the whole-suite-hostage vector
- **Why now.** The suite-scope vector (instances 7/12/13/14/17/18/19) keeps recurring, and the *authoring-time* advisory has just been widened to also scan `final_check` (task `self-improve-scope-advisory-finalcheck`, this same worktree) — closing the **authoring** half. But the advisory stays **warn-only** by design (scope is *perception*: legitimate whole-suite `verify_command`s exist), so a whole-suite check adopted against an already-red baseline can still false-FAIL a genuinely-green stage. The residual is the **decidable** half nobody yet mechanizes: "were these reds pre-existing at merge-base?"
- **The candidate.** A *differential verify* engine option: when a `verify_command`/`final_check` FAILS, the engine re-runs the SAME failed check at the branch's merge-base, and **subtracts the pre-existing reds** — a stage is green iff it introduces NO new failure. This turns the perception ("which reds are mine") into a decision the engine can make, without widening or narrowing the operator's check. It complements (does not replace) the scope advisory: the advisory nudges authoring; differential verify makes an unscoped-but-honest check safe at run time.
- **TRIGGER to promote from backlog → task.** Revisit if the suite/final_check-hostage class accrues another instance *after* this advisory extension lands (i.e. the authoring nudge proves insufficient on its own). **→ FIRED 2026-08-03 (instance 22 below): a whole-suite `verify-all` final_check false-failed on an inherited trunk red the ff-required rebase adopted — promote to task.**
- **REUSE pointer.** the `baseline_diff.py` helper on branch `si/baseline-diff-granularity` (its path there is scripts/lib/baseline_diff.py — not yet merged into this tree) already computes merge-base test-delta at line granularity — the differential-verify engine option should build on it, not re-derive the merge-base diff.
