# A gate must execute the artifact it attests, and every refusal it can issue must reach a resolution cycle

## Difficulty
A gate reports green while governing bytes it does not execute; and a gate that can refuse offers no transition into the cycle that resolves a refusal.

## Order & criterion
Notice the executed spec differs from the attested artifact (dispatch handed a stale stage after a legal PLAN_READY edit) -> read WHERE each cache is populated (submit-plan) vs WHERE the hash is taken (approve) -> refresh caches from plan_path inside approve, before the GateRecord, carry-key read before mutation -> separately, notice a refused final_check has no outgoing edge, confirm the 'diagnose' edge already exists in machine.py and only cli.py fails to fire it -> pin both with exact pytest node ids -> mutation-proof each pinned test against the reverted hunk.

**Acceptance check:** measurable: both pinned node-id tests FAIL against the un-patched cli.py and PASS with it (mutation proof run, not assumed); whole scripts/tests/ suite stays green (1508 passed).

## Common core & variations
**Common:** One functional ground with the two engine defects above: a gate or verifier is only as truthful as the thing it actually reads. Attest what you execute; announce only what you read; scan only what is under version control. Each instance reported GREEN (or a confident directive) while grounded in something other than the artifact it governed.

**Variations:** Three new instances. (1) VERIFIER DOMAIN: _iter_repo_files walked repo_root.rglob('*') though its own docstring promised 'tracked-shape' files, so the verdict was a property of one machine's scratch — an allowlist entry pinned a file that commit 77ce06c added to the allowlist but never committed: stale (red) in a clean checkout, matched (green) in a tree where the file existed untracked. Fixed with git ls-files plus a narrow fallback for non-git domains. The subtle part (caught by plan-review, not by me): find_ungoverned re-derives the domain with a SECOND independent rglob, so fixing only find_occurrences would have traded the stale-entry red for an ungoverned red. Induced rule: an allowlist entry ships in the SAME commit as the file it governs. (2) EXEMPTION KEY: five allowlist entries were pinned by line number into an append-only, machine-generated index; prepending one pointer shifted all five, and the mechanical re-pin would have carried zero review value. Key an exemption by the identity of the thing exempted, not by a coordinate that shifts for unrelated reasons. The grammar already supported a whole-file entry — no parser change, only data. Accepted residual risk recorded in the plan: a whole-file exemption is wider than its justification. (3) UNREAD ANNOUNCEMENT: cmd_critique asserted 'replan is now unblocked' from the presence of three record sections while gates.difficulty_blockers had since grown a shape check (>=2 distinct hypotheses, anti-template declaration) the announcement never learned about. Fixed by consulting the gate — and deliberately NOT firing it, since cmd_replan logs the same gate and test_gate_telemetry asserts an exact gates_fired list. (4) ABSENT PROVER (2026-08-04): the delivery gate refused `approve` with "no delivery proof recorded" on a machine where `hook-plan-delivery-gate.py` — the thing that WRITES the proof — was not registered in the root the session actually loads hooks from. There are two roots (`$CLAUDE_CONFIG_DIR`, else the CLI's own default root, for the harness; `$CLAUDE_AGENT_HOME` for the agent system — spelled out concretely in `scripts/agentctl/README.md` § Two config roots, which carries the allowlist entry for the literal) and under a bare `claude` they diverge by design, so the refusal was structurally unsatisfiable and said nothing about why. This is (b)'s twin one level out: (b) was a refusal with no reachable transition, this is a refusal whose *satisfier* is absent — the route exists but the gate blames the operator for not walking a road that was never built. Fix in three parts, none of which changes the verdict: a WIRED/ABSENT/UNKNOWN probe (`lib/hook_wiring.py`, three-valued so "I could not look" is first-class), consulted only OFF the hot path — the blocker text differs, the decision does not; a TYPED escape (`confirm-delivery --escape-reason`, a closed 5-value set validated in the command body rather than by argparse `choices=`, which would have hidden the flag from the argv-partition table); and a standing count (`scripts/escape-hatch-report.py`) so escapes stop being invisible — 3 of the first 5 delivery stamps on this machine were already overrides. Induced norm lifted to a principle leaf: [[verdict-covers-the-evidence-domain-it-claims]]. Two residuals: the escape-hatch INVENTORY is a hand-maintained declaration (the argparse name-pattern scan is only the reverse-direction test — a heuristic presented as an inventory would repeat this very defect at smaller scale), and one known non-argument hatch (`plan-review --verdict override`) does not fit the structure at all. (5) SELF-DISCHARGING GATE (2026-08-11): the sharpest form of the ground yet. The mandatory `question-enumerate` cross-check that gates `plan_approval` ran under a 20 s subprocess cap sized for the small `judge_*` calls, while a whole-plan enumeration is sonnet over a 100–270 KB plan and measures **15–170 s** — so the check ALWAYS timed out, and on timeout the gate **discharged itself**, recording `enumerate_pass` as satisfied. Distinct from (4): the prover was installed and running, so no wiring probe could have seen it; the fault was collapsing *"my own runner failed"* into *"the check passed"* — the third honest answer of [[verdict-covers-the-evidence-domain-it-claims]] collapsed into the **wrong** one of the first two, which is why (4)'s fix did not cover it. Fix in three parts: (i) the enumeration left the blocking path entirely — a **detached sidecar** worker launched at `submit_plan`/`replan` whose result is applied at `approve`, chosen after the user rejected a synchronous 449–512 s worst-case wait on `approve` at any level; (ii) a **typed, counted escape** (`premise.ENUMERATION_ESCAPE_REASONS`, 5 tokens) so `runner_ok=False` now BLOCKS and must be discharged explicitly, never silently — plus `verify-agentctl.py::check_enumeration_writers`, an AST pin on the writer set so a future bypass that flips `enumerated_runner_ok` outside a real pass fails the verifier; (iii) the ceiling **re-derived from a measured dataset** (15 rows, 5 plan sizes × 3 repeats, collected under a 600 s `MEASURE_CAP` so no row was truncated by the bound being measured) rather than guessed, shipped as 480 s with the dataset committed. Because that dataset ships in a PUBLIC repo, its `plan_path` field was stripped at the resolution gate — `plan_sha256` identifies a row without naming a local path. Residual OPEN-3: `cmd_ledger_enumerate` inherited the 480 s ceiling in the **foreground** (it gates nothing, so it was deliberately not detached); if that wait bites, reuse the sidecar rather than narrowing the ceiling back. Three norms lifted to principle leaves: [[a-judging-artefact-is-executed-before-it-judges]], [[shared-resource-health-asserted-relative-to-a-pinned-base]], [[renorming-at-principle-level-sweeps-the-class]].

## Self-critique of the agent system
I wrote a vacuous control criterion twice in one task (shell backtick substitution inside a double-quoted python -c; then 'pytest -k verify_final' substring-selecting an unrelated pre-existing test). Both times the verify_command COULD NOT FAIL, so it was not a control. Mutation proof must be the standing discipline, not a remedy applied after a reviewer catches it. Separately: a budget-cap exit prints MALFORMED and the engine routes to BLOCKED even when the work is complete — the manager then re-verifies by hand; the wrapper should distinguish 'no marker because capped' from 'no marker because failed'.

2026-08-04 (instance 4): the PLAN nearly reproduced the very fault it was written to remove. Stage 6 originally treated `git add`-ing a new artifact as if it discharged the verifier's obligation, when staging only makes the artifact VISIBLE to a checker that enumerates from the git index — two acts, not one, and conflating them yields a stage that is green because nobody has looked yet. It took two review rounds to separate them. The generalized form is now a principle leaf; the operational form is the task-wide staging invariant (stage every new .py BEFORE regenerating crutch_registry.toml). Separately, the ESCAPE-HATCH inventory shipped as a hand-maintained declaration rather than a scan, deliberately — a name-pattern regex presented as an inventory would have been this same defect at smaller scale — but that leaves the inventory's completeness resting on whoever edits it next, which is exactly the kind of unmeasured residual this leaf keeps rediscovering.

2026-08-11 (instance 5): $52.80 and 636 active minutes to ship ~250 lines, and the deliverable was **never** what failed. Four consecutive replans came from defects in the plan's own controls, each discoverable only by running one — which nothing on the `submit_plan` path does. I hand-walked that gap the whole task (materializing controls into `/tmp/preflight/` and running them before submitting) instead of proposing the structural form, which is exactly the "hand-walking a deterministic chain is the signal that mechanism is missing" rule in CLAUDE.md; the `agentctl` read-only control pre-flight is now filed as the headline defect, not shipped. Second: the same shared-resource-control form was corrected at three separate sites across three replans before I looked for its siblings — the discipline is now [[renorming-at-principle-level-sweeps-the-class]], but it took a third occurrence inside ONE task to see it. Third, discovered at the resolution gate: the `review_dispatch` obligation key is `…|code_review|<stage_index>`, so an obligation raised against v1's stage 3 (then a `spawn:developer`) survived the full replan that made stage 3 an `in_thread` doc stage — an obligation keyed by a coordinate that a replan reassigns, which is the (2) EXEMPTION-KEY variation above repeating on a different record type. Fourth, publication hygiene held only by accident: the calibration dataset carried 5 absolute local plan paths and this repo is public — caught at the gate by asking "is this publishable?", a question nothing on the spine asks.
