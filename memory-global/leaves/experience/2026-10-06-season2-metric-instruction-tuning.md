# Tuning the agent's own instructions to an external productivity metric (AI Profile Season II)

## Difficulty
An external productivity score (the org's AI Profile, Season II) changed how it counts: parallelism became the number of distinct Claude Code session ids, tool breadth became distinct MCP servers plus skills per day, and productivity became merged PRs whose files were touched through Edit/Write/MultiEdit (a shell `sed -i` is not attributed; the personal junk/ area is blacklisted). The agent's own norms pointed the other way on three axes: plan review ran sequentially by default, dispatch preferred direct CLI and skills over a covering MCP server, and in auto mode source edits went through shell writes the metric cannot see. The normative gap was the easy part; the process paid for four secondary difficulties: (1) 14 plan-review rounds because the driver ran WITH early stop, so 10 of 17 pairs on levels 2-7 were never reviewed or cached and every resubmission re-reviewed from level 1 - and the proposed remedy, review only changed stages after round 5, borrowed the number 5 from the engine's round-release threshold with no mechanism behind it, which the user caught (the engine already scopes per pair via gates.pair_status; the missing piece was the driving rule: plan-review-walk first, then the driver with --no-early-stop); (2) the new PreToolUse hook tracks only a LEADING `cd <dir> &&`, so a fixture-creation command that cd'd later in a compound was denied as a write into canon; (3) in the org's second VCS the local trunk ref was stale after a rebase onto it, so the writable mount still showed the old leaf until a second rebase onto the REMOTE trunk ref after an explicit fetch; (4) at the end the root filesystem hit ENOSPC (22 abandoned pytest basetemp dirs with dead-pid locks, 6.3 GB), child stdout was lost, and the canonical second-VCS mount dropped mid-turn; the canon verify-all is also red through a foreign uncommitted leaf of another live session, which the user chose to wait out rather than stash.

## Order & criterion
Research the Season II metric code and tune the agent's instructions to it, user-scoped: A3 parallel plan review by default (agent's reasoned width, not a borrowed constant) and continue past a revise level (O5, folded in as R7 from a self-improvement correction); A4 responsiveness norms (one-line progress while spawns run, no silent gaps); B prefer a covering MCP tool, else a skill, inline/spawn by appropriateness; C Edit/Write/MultiEdit only for source edits, backed by a structural PreToolUse hook; D no idle work done only to move the metric. A1/A2 deferred until the user's profile data arrives; junk/ and GitHub work stays.
