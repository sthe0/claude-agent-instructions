# a-users-revising-decision-reads-as-settled-though-its-technical-premise-was-never-checked

## Regularity

When a user's decision replaces an earlier one already built into the plan, the new decision reads as settled fact because the user decided it, not because its own technical premise was checked against code. Recorded straight into the done criterion or a final check, the unverified premise passes through several plan-review rounds and surfaces only when an independent reviewer or a landed run contradicts it, leaving a stage assertion built on it.

## Generality

Level 1 — ranges over user decisions that replace an earlier decision already reflected in a plan's done criterion or final check. It is deliberately not claimed for first decisions, whose premises enter review together with the plan.

## Induced from

- [[own-research-precedes-escalation]] — contributes the observed case of a user-approved architecture revision wired into a done criterion and final check across three review rounds before a fourth caught its unverified runtime-routing premise.

## Refutation

Revising decisions found, in a sample of plans, to have their technical premise caught in the first review round as often as premises of the original decisions.
