# Hooks

> The harness-run scripts that enforce the non-skippable gates and fire the reminders — the deterministic guardians that make the coordination spine binding rather than advisory.

A hook is a script the Claude Code harness runs on an event (prompt submit, before a tool call, on stop). Because the harness — not the model — executes them, hooks can **deny** a tool call outright, which is what makes a gate non-skippable. The hook scripts live in [scripts/](../../scripts/) as `hook-*.py` and are installed into the active settings by `setup-symlinks.sh` (via `install-reminder-hooks.sh`); the settings surface they attach to is described in [settings-and-permissions.md](settings-and-permissions.md) and under [settings/](../../settings/README.md).

The hooks fall into two roles:

- **Gate guardians (hard-deny).** [hook-state-gate.py](../../scripts/hook-state-gate.py) is the load-bearing one: it denies production edits until the coordination engine reaches an execution node, enforcing the plan-approval gate (and refusing a plan-file edit during execution, which must instead route through replan). [hook-engine-start.py](../../scripts/hook-engine-start.py) auto-arms the engine on the first prompt so the gate is active from the start.
- **Bash source-edit guard (hard-deny).** [hook-guard-bash-source-edit.py](../../scripts/hook-guard-bash-source-edit.py) closes the shell side channel around the production-edit gate: `hook-state-gate.py` and `hook-scope-conflict.py` see only `Edit|Write`, so it denies a `Bash` write of literal text (`sed -i`, `perl -i`, a redirect from `echo`/`printf`/a stdin-only `cat`, or `tee`) into a tracked source tree — a git work tree or a directory under an ancestor carrying a `.arc` marker directory — and points at Edit/Write instead. Scratch and memory roots are allowed; unparsable input fails open. The verdict reads shell shape and target location, never the written text. Design and residuals: [bash-source-edit-guard.md](../decisions/bash-source-edit-guard.md).
- **Retrieval channel (nudge, never block).** [hook-memory-retrieval.py](../../scripts/hook-memory-retrieval.py) ranks the prompt against every memory leaf with the shared BM25F scorer ([lib/bm25f.py](../../scripts/lib/bm25f.py)) and prints up to three candidate pointers, so a recorded norm is in front of the model when its trigger arrives. The score only nominates; the model judges relevance, which is why the site is inventoried as candidate-generation. No judge call, no network, fail-open. Its cutoff is measured, not chosen: [memory-retrieval-calibrate.py](../../scripts/memory-retrieval-calibrate.py) writes [memory-retrieval-calibration.json](../operations/memory-retrieval-calibration.json). See [memory-usage.md](../../memory-global/leaves/memory-usage.md) § Retrieval channel.
- **Reminders (nudge, never block).** A family of `hook-*.py` scripts surface the right discipline at the right moment without denying the call — among them [hook-resolution-reminder.py](../../scripts/hook-resolution-reminder.py) (ask the user to confirm resolution rather than assume it), [hook-skill-first.py](../../scripts/hook-skill-first.py) (prefer an MCP tool or a matching skill over hand-rolled Bash), [hook-retry-detector.py](../../scripts/hook-retry-detector.py) (a repeated failure is a difficulty to overcome).
- **Per-prompt reminders and due checks (nudge, never block).** Two hooks replace what were seventeen scripts. [hook-prompt-reminders.py](../../scripts/hook-prompt-reminders.py) (`UserPromptSubmit`) runs the context-growth, behavior-feedback (self-improvement), tracker, tracker-publish, ticket-plan-sync, experience-record, language and instructions-refresh reminders in one process and speaks only when a reminder's own condition holds; the language reminder fires at most once per session. [hook-session-due.py](../../scripts/hook-session-due.py) (`SessionStart`) runs the throttled due checks (instruction grooming, self-diagnose, phase-3 readiness, promote-scan, policy scorecard, budget calibration, sigma sentinel, improvement-scan, judge ceiling drift) under one 20 s budget, each against its own stamp file and interval (`DUE_INTERVALS_S`).

The two gates the guardians protect — plan-approval and resolution — are the same two gates on the state machine described in [the coordination engine](../architecture/coordination-engine.md). `verify-agentctl.py` checks that every gate still has its guardian hook wired up.
