# Coordination constants — rationale

The keys and values live in [`config.md`](../../config.md), which is loaded into every session and so carries one plain line per key. This page holds the full meaning and basis of every key, read on demand. The intro, the table and the closing paragraphs below are the former `config.md` text, moved unchanged (the table's Meaning column is the full former meaning; the Value column duplicates `config.md`, which is authoritative).

Single source of truth for the numeric constants used by the coordination machinery defined in `CLAUDE.md`, the cursor mirror, and the skills. Imported into every Claude Code session via `@~/.claude-agent/config.md` at the end of `CLAUDE.md`.

Edit values in `config.md` — not in the prose that references them. Every cross-reference uses the **key**, not the literal value. Where a mechanical surface (spawn template, shell script) must embed a literal number, an inline comment names the key so `rg <key>` still finds the use site.

| Key | Value | Meaning |
|---|---|---|
| `max-recursion-depth` | `5` | Hard cap on `AGENT_RECURSION_DEPTH`. A spawn that would push the env var to a value **above** this is forbidden — escalate to the user instead. Applies to every `claude -p` invocation, including `overcome-difficulty`'s recursive escape. |
| `loop-sensitivity-depth` | `2` | At this depth and deeper, a spawned level must self-check whether its task is a re-framing of an ancestor's task and return `LOOP_DETECTED:` early rather than recursing further. |
| `budget-small-usd` | `1.00` | Expected-size **telemetry label** for small specialist work (single-file edit, narrow analysis, short plan refinement). NOT a kill-cap — under flat billing the dollar figure is list-price telemetry, not marginal money (leaf `flat-max-billing-cost-framing`). Recorded on the spawn-costs row and used for the soft-warn; the actual `--max-budget-usd` kill is `spawn-runaway-ceiling-usd`. |
| `budget-medium-usd` | `3.00` | Expected-size **telemetry label** for typical specialist work (multi-file change with tests, scoped refactor, standard plan). Default tier — pick when in doubt. Also the default for `overcome-difficulty`'s recursive escape. Label only, not a kill-cap (see `budget-small-usd`). |
| `budget-large-usd` | `8.00` | Expected-size **telemetry label** for cross-cutting changes (multi-stage plan, full feature, expensive research). Label only, not a kill-cap (see `budget-small-usd`); also the fail-safe fallback for `spawn-runaway-ceiling-usd` if that key is ever absent. |
| `spawn-runaway-ceiling-usd` | `25.0` | Single global **runaway backstop** passed as `--max-budget-usd` to every spawn, regardless of tier. Under flat billing the tier labels ($1/$3/$8) are NOT money limits; this ceiling exists only to kill a runaway/looping spawn — protecting the constraints that ARE scarce on flat (rate-limit headroom, wall-clock, attention). Set well above the large tier (~3×) so legitimate large work is never truncated. If this key is absent, spawn machinery falls back to `budget-large-usd` (never unbounded). |
| `small-change-max-lines` | `20` | Upper bound (line count) for the *small change* class in task triage. ≤ this many changed lines + single file + no architectural decision = manager may handle in-thread without a plan-approval gate. |
| `substantive-wall-clock-min` | `30` | Lower bound (minutes) for the *substantive* class in task triage — work expected to take this long or more warrants the full coordination cycle. |
| `rediscovery-threshold-min` | `5` | Quality bar for post-resolution experience leaves — record if skipping the leaf would cost a future similar task at least this much rediscovery. |
| `claude-md-max-lines` | `400` | Hard ceiling on `CLAUDE.md` line count. Above this, extract a section to a `memory-global/leaves/` leaf and reference it. Enforced by `scripts/lint-prose-length.py`. |
| `claude-md-max-chars` | `39500` | Hard ceiling on `CLAUDE.md` size in UTF-16 code units (chars) — the unit the harness itself measures (`content.length`), NOT UTF-8 bytes. The harness's own threshold is `max(40000, round(window * 0.05 * charsPerToken))` (function `fXr()` in the installed `@anthropic-ai/claude-code/bin/claude.exe` bundle; constants `dny=40000`, `uny=0.05`, fallback window `ber=200000`). `window` here is the MODEL's context window, not the `autoCompactWindow` pin, and `charsPerToken` is 3 for every model outside the legacy `esg` set (which is 4) — so on the current `claude-opus-5[1m]` the live threshold is **150 000 chars** and the 40 000 floor does not bind at all. The floor binds only when the window drops to 200 000: either the model alias carries no `[1m]` (test `Wb()`), or 1M credits are blocked (`H9t()`, which clamps to `gxe=200000`). `CLAUDE_CODE_DISABLE_1M_CONTEXT` is NOT the gate — it appears nowhere on this path and is set nowhere in this fleet. Crossing the threshold produces a DISPLAY-ONLY `/doctor` warning (the `large-memory-files` status card `Xqb`, whose `isActive` filters via `mXr()`) — there is NO truncation on the memory-file load path. Re-verified 2026-07-28 against client 2.1.220 by reading the bundle; the 2026-07-23 over-limit sentinel test (a tail sentinel past 40 000 chars returned verbatim) still stands. These are CLIENT-SIDE constants Anthropic can change in any release, and the minifier renames the functions between builds (`dYr()` → `fXr()` within 2.1.220 alone) — re-find the card by the literal string `large-memory-files` rather than by symbol name, and re-read rather than re-derive. Enforced by `scripts/lint-prose-length.py` (the line-count guard does not catch char growth). |
| `readme-max-lines` | `140` | Hard ceiling on README.md line count — README is the thin entry-point; everything deeper lives under docs/. Enforced by scripts/lint-prose-length.py. |
| `cursor-mirror-max-lines` | `220` | Hard ceiling on `cursor/rules/claude-code-sync.mdc`. The mirror is thin by design. |
| `skill-md-max-lines` | `200` | Hard ceiling on any `skills/*/SKILL.md` or `skills/specializations/*/SKILL.md`. Detail belongs in a sibling `policy.md` or a memory leaf. |
| `policy-md-max-lines` | `400` | Hard ceiling on any `skills/*/policy.md`. Policies are allowed to be detailed but not unbounded. |
| `core-difficulty-mass-threshold` | `8` | Cluster mass (Σ severity over the severity-weight ladder low=1/medium=2/high=4/critical=8) at/above which a Core-difficulty cluster is flagged for a batched Core change (ADR-0001 § Difficulty-accumulation). Consumed by the digest `core-difficulty-digest.py`. **Basis:** `8` = four independent medium reports (4×2) or two high (2×4) — the recurrence point at which a difficulty has been reported enough to warrant a Core change rather than a one-off; any single critical short-circuits to flag regardless. Derived from the ladder, not guessed; recalibration guidance in `docs/architecture/core-difficulty-calibration.md` (ADR open question #2). |
| `difficulty-channel` | `github` | Channel for filing Core difficulties from non-author machines, **auto-detected** per machine by `scripts/difficulty_channel/detect.py` (a machine-local detect hook may claim the machine for its own channel; otherwise → `github`) and written to `~/.claude-agent/agent-identity.local` (`difficulty_channel=<name>`); override by editing that line. Values: `github` (GitHub Issues sthe0/claude-agent-instructions — the built-in, org-neutral default) or the name of an adapter a higher layer installs through the plugin seam (`<agent-home>/difficulty-channel-plugins/adapters/<name>.py` — opt-in, credentials supplied by that layer). | `advisor-mode` | `substantive` | Activation mode for the agentctl advisory judge (`advisor.resolve_enabled`): `off` = never auto-activate, `substantive` = auto-activate at the four cognition points when the session's weight class is SUBSTANTIVE. The `AGENTCTL_ADVISOR` env var overrides in both directions (`1` forces on, `0` forces off); a missing key resolves to off. Two separate cost bounds govern two separate call shapes: the four `judge_*` cognition points keep `--model sonnet` + a hard 20 s subprocess timeout (`advisor._ADVISOR_TIMEOUT_S`), sized for a small payload; the claim enumeration behind `ledger-enumerate` (`advisor.enumerate_claims`) instead runs through `advisor.ENUMERATE_TIMEOUT_S` = 480 s (env-overridable via `AGENTCTL_ENUMERATE_TIMEOUT_S`), derived from measured fleet latency — see `docs/operations/advisor-timeout-calibration.md`. | `child-contour-linking` | `on` | Kill switch for linking a spawned specialist into its own engine contour (ADR-0010): `on` = a spawn naming a parent `--session` and `--stage-index` gets a norm handoff, its own engine session and the own-contour channel; `off` = every spawn is unlinked, the pre-linking path. Allowed values `off` \| `on`; resolved only by `agentctl.config.child_contour_linking_enabled`, which `spawn-specialist.py` calls at its one decision point. The `AGENTCTL_CHILD_LINKING` env var overrides in both directions (`1` forces on, `0` forces off); a missing row, any other value or an unreadable config.md resolves to off. Basis: user decision 2026-10-13 — the contour's known gaps make parallel sessions stumble, so linking ships off until they are closed; turning it on is this one line. Switched `on` by the linking-trial: the breaks of its trials A-C and C2 were fixed in the trial and its post-fix re-runs A2 and C3 had no blocking failure, as pinned in verdict-re.json by re.sha256 (sha256 of verdict-re.json `ce09c273e5053e9bd51836c9737eaf84bb7c68e93d44c2e4fc6c3cac04e07a0c`); `AGENTCTL_CHILD_LINKING=0` still turns linking off per spawn. |
| `principle-promotion-threshold` | `3` | Occurrence count (Σ `### ` context blocks across an experience-leaf cluster sharing one functional ground) at/above which `record-experience.py promote-scan` flags the cluster as a candidate to lift into a regularity/v1 leaf (the knowledge layer; a principle is then grounded in regularities). Distinct from `core-difficulty-mass-threshold` (severity-mass for Core edits) — this is a **recurrence count** for regularity induction. Basis: the Rule of Three (Fowler, *Refactoring* 2nd ed.) — two occurrences may be coincidence; a third establishes a recurring pattern worth generalizing. Tunable here. |
| `skill-description-max-chars` | `850` | Hard ceiling on a `SKILL.md` frontmatter `description:` value — always-visible index cost (loaded into every session's skill list), unlike the skill body, which loads only on invocation. Measured 2026-07-23: the longest of the 11 current skill descriptions is 793 chars (`skills/specializations/developer/SKILL.md`), so `850` leaves headroom while still catching runaway growth. Enforced by `scripts/lint-prose-length.py`. |
| `always-loaded-surface-advisory-chars` | `80000` | ADVISORY-only (never FAIL) ceiling on the aggregate always-loaded surface — CLAUDE.md + config.md + `memory-global/MEMORY.md` + the sum of every skill's frontmatter description. Report-only via `scripts/lint-prose-length.py --surface-report`; deliberately not enforced, because an aggregate ceiling incentivizes deleting someone else's rule to stay under budget rather than fixing your own contribution (the 2026-07-03 regression this guards against). Measured 2026-07-23 aggregate ≈ 75 700 chars (via `scripts/lint-prose-length.py --surface-report`). The same command also prints a PRICE block that converts this total into a measured tokens-per-step cost against a live transcript window, replacing enforcement with a marginal-cost signal at edit time. |
| `memory-index-max-bytes` | `24000` | Hard ceiling on `memory-global/MEMORY.md` size in UTF-8 **bytes** — the harness caps this file at `rxe=25000` bytes / `Doe=200` lines (function `Yqr(e)`, AutoMem path) and truncates silently; the 1000-byte margin, why bytes bind before lines, and why the byte-unit choice is safe under either reading of `rxe` are in [memory-index-max-bytes-derivation.md](../../memory-global/leaves/memory-index-max-bytes-derivation.md). Unlike `always-loaded-surface-advisory-chars` this is a PER-FILE ceiling enforced by `scripts/lint-prose-length.py`. |
| `phase3-due-sessions-floor` | `30` | Minimum scanned sessions before an OBSERVED firing verdict is treated as evidence rather than coincidence, in the Phase-3 readiness predicate (`scripts/rule-salience-report.py --check-due`). Basis: the report's own default window is 90 days (`--days`), and at the observed session cadence 30 sessions is the point at which a rule that fires on a common trigger has had many independent opportunities; below it, a single busy day could supply the whole sample. Recalibrate here. |
| `phase3-due-data-window-days` | `14` | Minimum elapsed days since the Phase-3 sentinel's baseline stamp (`~/.local/state/claude-phase3-baseline.stamp`) before its verdict is trusted. Basis: the user-agreed two-week minimum, so a NEVER-OBSERVED rule means "really does not fire" rather than "not yet seen"; it is also 2× the 7-day throttle the repo's other `*-due` hooks use, so at least two evaluation cycles fall inside the window. |
| `effort-divergence-multiple` | `5.0` | Ratio of accumulated actual effort to the current plan's re-derived estimate at/above which the effort-divergence trigger routes the session to DIAGNOSING, on either ratio scale (spend, active wall-clock). Basis: 5–10× is the band the ORDER stipulated, not a derived interval; what is derived is which end to take — the low one, because the errors are asymmetric (a false positive costs one declare→investigate→critique cycle, a false negative costs the whole remaining overrun, which is unbounded). Deliberately **no separate numeric floor row**: the trigger is armed-only and a zero estimate is inapplicable rather than infinite, so the floor the order asked for is implied — smallest firing overrun is 5 × `budget-small-usd` = **$5.00** on spend and 5 × `effort-stage-minutes-small` = **50 active minutes** on wall-clock. Derivation in full: `scripts/agentctl/README.md` § Effort divergence. |
| `effort-stage-minutes-small` | `10` | Expected ACTIVE wall-clock minutes for a `small` cost-tier stage — the wall-clock companion to `budget-small-usd`, and the row `in_thread` stages are priced at (in-thread work consumes wall-clock though it consumes no attributable spend). Basis: all three rows share ONE anchor, `substantive-wall-clock-min` (30) — 1/3 of it here, ~5/6 at medium, 2× at large. They are NOT proportional to the dollar tiers ($1→$3→$8 is 3×/2.7×; 10→25→60 is 2.5×/2.4×): same ordering, different ratios, deliberately, since a tier's dollar size is driven by model spend and its wall-clock size by how long a person waits. Do not "correct" one ladder to match the other. |
| `effort-stage-minutes-medium` | `25` | Expected ACTIVE wall-clock minutes for a `medium` cost-tier stage — companion to `budget-medium-usd`. Basis: just under `substantive-wall-clock-min`, i.e. the largest stage that is still a stage rather than a task of its own. Shared anchor and the don't-match-the-dollar-ladder rule: see the `small` row. |
| `effort-stage-minutes-large` | `60` | Expected ACTIVE wall-clock minutes for a `large` cost-tier stage — companion to `budget-large-usd`. Basis: 2× `substantive-wall-clock-min`, a stage that is itself a substantive task's worth of work. Shared anchor: see the `small` row. |
| `effort-replan-absolute` | `5` | Replan count on the current plan at/above which the effort-divergence trigger fires regardless of the multiple, on the replan-count scale. Basis: the value `5` is a user decision (2026-09-28), raised from `3`: within this same threshold, an agent operating inside the autonomy boundary (`gates.autonomy_boundary` — a self-approved replan of an order the user already approved, whose resources stay within the last user-approved version plus the customer's stage-scoped grants, and whose only changed unresolved commands are engine-executed fixed texts — `verify_command` / `negative_control` / `final_check` — vouched for by a first whole-plan thinker pass; a changed declared or output-artifact-derived rule goes to the user) runs its own overcome-difficulty cycle on the fire and continues on the corrected plan without asking the user, so the wall a purely user-facing threshold of `3` was calibrated against is no longer the wall this number bounds — `5` gives the agent's own planning-difficulty cycle room to fire and resolve before the reopen/round-release ceilings below engage. The original `3` shared `principle-promotion-threshold`'s recurrence basis — two replans may be ordinary refinement; a third establishes a recurring difficulty worth diagnosing rather than replanning again. Also governs the pre-approval review-round count (`state.plan_review_rounds`, incremented per PLAN_READY resubmission made while a review record stands — redrafting a plan nobody has reviewed yet is not a round — and reset on approval): at this same threshold, `gates.plan_review_round_release_active` stops requiring a further thinker review and routes the outstanding blockers to an explicit decision, recorded as `plan-review --verdict override`, instead — the user's, or the coordinator's own — the engine admits an agent-authored override only while this round release or the cross-axis friction release is active, never counts it as a thinker pass for the autonomy boundary, and does not keep it silent: the directive that carries the plan to the user names it (`data['agent_review_override']`: reviewer, scope, note, plan path) so the user sees the review was waived, not passed — one row, no new key. |
| `effort-replan-backstop` | `6` | Replans the task has accumulated since the last decision the USER took (an approval, a fire-acknowledgement, a renegotiation, a plan-review override, or a `task-reset` — the one-line list in `task_accumulator.clear_since_user_decision`) at/above which the agent may no longer acknowledge an effort fire or continue a renegotiation itself (`cli._agent_self_decision_refusal`); the decision then goes to the user — except inside the autonomy boundary the user approved (`cli._autonomy_for`, the predicate the next `approve --by agent` is held to), where a `revise` acknowledgement of a replans fire or a renegotiation `continue` stays the agent's while at least one spend or wall-clock ratio is armed and every armed ratio is below `effort-divergence-multiple`, both measured since the last user approval. Basis: `max(p90, effort-replan-absolute + 1)` with `p90 = sorted(v)[min(n-1, round(0.9*(n-1)))]` over the replans-per-segment population of **258** segments between user-authored decisions, exactly as armed in `docs/operations/review-backstop-arming.json` (replans p90 = 2, so the `effort-replan-absolute + 1` floor binds and the value is `6`). Why a floor and not the bare p90: the agent's own continue decision zeroes the ceiling counters, so a backstop at or below `effort-replan-absolute` would refuse the very decision that threshold exists to let the agent take. Spend and wall-clock fires stay user-owned regardless of this row. A missing or unparsable row falls back to `effort-replan-absolute + 1`. |

Raised from 256 on 2026-10-13 (user decision): the headroom is computed once at launch and shared with every other session's threads, so a concurrent suite (a reviewer's run) ate it and a capped run failed with EAGAIN; 512 fits several concurrent suites, memory (~150–170 Python processes, ~14 GB of 37 GB free) stays the looser bound, and the hard per-user ceiling (204686) is far above. The literal lives in `scripts/cap-run.sh` with this key name in a comment. Re-measure if the suite grows markedly. |
| `fanout-cap-timeout-s` | `3600` | Wall-clock limit, in seconds, for one capped fan-out trial. Basis: 3× the serial full-suite wall-clock of 1099 s measured 2026-10-07 (the parallel run took 299 s), so a legitimate run is never cut while a hung one is still bounded. The literal lives in `scripts/cap-run.sh` with this key name in a comment. |

| `plan-stage-max-chars` | `70000` | Largest rendered size, in characters, of one stage or of the plan-level node (`[meta]` with `[meta.order]`) in the base role, every field inline (`plan.stage_rendered_size` / `meta_rendered_size`); a node over it blocks `submit-plan` and its topological review is refused before any spawn, with no waiver. Basis: `S = floor((C - O) / 3)` rounded down to a multiple of 1000, where `C` is the dispatch prompt ceiling (`lib.spawn_ceiling.dispatch_prompt_ceiling_chars`) and `O` the pair-review prompt around the nodes: the normalized prompt on a fixture of empty nodes plus `n_p * P`, the allowance for its `n_p` path placeholders turning back into real paths (`P` = the longest real path a placeholder stands for, the view root at `topo_units_root()`, minus the shortest placeholder). A pair prompt shows three nodes — the plan-level node, the base and the service — so three nodes of `S` and `O` fit under `C`. The measured values are in `docs/operations/plan-size-calibration.json`; regenerate with `python3 scripts/plan-size-calibrate.py` (`P` reads this machine's longest path, so regenerate where the prompts are built). A node limit alone cannot bound a prompt (review history and spawner sections are not nodes), so the topological driver also refuses a prompt over `C`. Every seam that admits plan bytes (`submit-plan`, `approve` after an in-place edit, `replan`, a renormalizing replan) refuses a node over the limit. The row fails closed: a missing or non-integer row refuses plan submission and topological review with a message naming the row, rather than guessing a limit. |
| `plan-field-inline-max-chars` | `3000` | Longest prose field a plan prints inline, in characters: a longer one reads as `see objects/<sha256>` in a view, and `submit-plan` warns that it should be externalized (`agentctl plan-externalize`). Basis: `F = floor(S / k)` rounded down to a multiple of 500, with `S` = `plan-stage-max-chars` and `k` = 23, the largest per-node-kind count of fields a plan may hold in a file of their own (`plan_refs.EXTERNALIZABLE_FIELDS`, the stage), so a node whose every such field sits at the limit still fits under `S`. Derivation and regeneration: see `plan-stage-max-chars`. Unlike that row, this one only advises (a warning, a view's inline cut), so a missing or non-integer row falls back to `agentctl.config.PLAN_FIELD_INLINE_FALLBACK_CHARS`, equal to the calibrated value (a test keeps the two equal). |
| `reaper-pressure-free-percent` | `10` | Free-space percentage (`f_bavail / f_blocks` of the filesystem holding a path a reaper names in its `pressure_paths(ctx)`, the figure `df` calls available) strictly below which `scripts/hook-reaper.py --on-pressure` makes that reaper due without waiting for its 24-hour throttle; a per-reaper cooldown (`PRESSURE_COOLDOWN_MIN` in `scripts/reaper/runner.py`) keeps a full disk from starting a pass at every turn end. Every other reaper still scans and vetoes, and a reaper's own safety rules are unchanged: pressure changes when a reaper runs, never what it may delete. Basis: a stock ratio, not a fill-rate margin — on 2026-10-23 the pytest temporary directories held 49 GB on a 492 GB volume, 9.96 percent, rounded up to `10` so that the free space left always has room for one incident-sized stock. An initial value, recalibrated from `pressure.jsonl`; too high costs one cheap scan per cooldown, too low lets the incident repeat. `<config root>/reaper/pressure.jsonl` records the free percent and removed count of every pressured pass; recalibrate from it. A value that is missing, not a number, or not strictly between 0 and 100 disarms the mode: no pressured pass runs and `--on-pressure --dry-run` says `disarmed`. |
