# judge-prose-domain.txt — the files whose PROSE explains judge latency, and
# whose numbers therefore go stale when the calibration moves. One repo-relative
# path per line; `#` comments and blank lines ignored.
#
# The domain is a committed list rather than a repo-wide sweep because it is the
# reviewable object: adding a file here is a decision that its prose is governed,
# and verify-judge-prose-numbers.py fails on a path that no longer exists, so the
# list cannot rot into a no-op. A file NOT listed here is prose nobody promises to
# keep in step — if you write a judge duration into one, add it here in the same
# commit.
#
# Membership rule: the file's comments / docstrings / body state a judge duration
# or one of its sample statistics. Files that merely CALL a judge without
# explaining a number stay out.

# The calibration itself, and the arithmetic that consumes it.
scripts/lib/judge_latency.py
scripts/lib/judge_budget.py

# The three judge-calling hooks: each holds its own budget, ceiling and floor
# constants and explains them in comments.
scripts/hook-turn-end-gate.py
scripts/hook-deferring-disposition-gate.py
scripts/hook-escalation-diagnosis-gate.py

# The last-resort defaults on the judge signatures, and the advisory timeout the
# non-judge calls keep.
scripts/agentctl/advisor.py

# The harness-registered timeouts, and the requirement table that pins them.
scripts/install-reminder-hooks.sh
scripts/lib/hook_wiring.py

# The raw samples' own write-up: every number in it is a measurement or a
# feasibility statement about a budget.
samples/judge-latency/README.md

# The live-run evidence: the densest judge-latency prose in the repo — every
# number in it is either a measured run or a statistic recomputed from a sample.
live-run-evidence.md
